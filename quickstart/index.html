Quick Start Guide

From zero to production-ready code in 5 minutes. Let's build your first spec-driven application with AWS Kiro.

⏱️ Estimated time: 5 minutes
1
Install
2
Initialize
3
Specify
4

1

Install AWS Kiro

Choose your platform and install Kiro with a single command:

🍎 macOS (Homebrew) 
brew install awslabs/tap/kiro
📝
Don't have Homebrew? Install it first with: /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
🐧 Linux / WSL 
curl -fsSL https://kiro.aws/install.sh | sh
💡
Ubuntu/Debian users: You can also use APT: sudo apt-get install kiro
🪟 Windows (PowerShell) 
irm https://kiro.aws/install.ps1 | iex
⚠️
Note: Run PowerShell as Administrator for system-wide installation.
🐳 Docker 
docker pull aws/kiro:latest
docker run -it --rm -v $(pwd):/workspace aws/kiro:latest

Verify Installation

Terminal 
kiro --version

You should see output like: kiro version 1.0.0

2

Initialize Your Project

Create a new directory and initialize Kiro:

Terminal 
mkdir my-kiro-app && cd my-kiro-app
kiro init

This creates the following structure:

Project Structure 
my-kiro-app/
├── .kiro/
│   ├── config.yaml      # Kiro configuration
│   ├── specs/           # Specification files
│   └── hooks/           # Custom hooks
├── src/                 # Generated source code
├── tests/               # Generated tests
└── README.md            # Project documentation
💡
Pro Tip: Run kiro doctor to verify your environment is properly configured.
3

Write Your First Specification

Create a specification for a simple REST API:

Terminal 
kiro spec create todo-api

Edit the generated specification file:

.kiro/specs/todo-api.yaml 
apiVersion: kiro.aws/v1
kind: Specification
metadata:
  name: todo-api
  description: Simple TODO list REST API
spec:
  requirements:
    - id: API-001
      description: |
        The system SHALL provide a REST API for managing TODO items
        with the following operations:
        - Create a new TODO
        - List all TODOs
        - Update a TODO
        - Delete a TODO
      
    - id: API-002
      description: |
        WHEN a user creates a TODO
        THEN the system SHALL validate the title is not empty
        AND assign a unique ID
        AND return the created TODO with 201 status
      
    - id: API-003
      description: |
        TODO items SHALL have the following fields:
        - id (string, UUID)
        - title (string, required, max 200 chars)
        - completed (boolean, default false)
        - created_at (timestamp)
        - updated_at (timestamp)
  
  architecture:
    type: rest-api
    framework: fastapi
    database: sqlite
    
  testing:
    coverage: 80
    types: [unit, integration]
📝
EARS Format: Notice how we use "SHALL", "WHEN/THEN" patterns for clear requirements.
4

Generate Production Code

Now generate the code from your specification:

Terminal 
kiro generate

Kiro will create:

  • Complete FastAPI application with all endpoints
  • SQLite database models and migrations
  • Input validation and error handling
  • Comprehensive unit and integration tests
  • API documentation (OpenAPI/Swagger)
  • Docker configuration
  • README with setup instructions

Run Your Application

Terminal 
# Install dependencies
pip install -r requirements.txt

# Run the application
uvicorn src.main:app --reload

# In another terminal, run tests
pytest

Your API is now available at http://localhost:8000 with docs at /docs

🎉
Congratulations! You've just created your first spec-driven application with Kiro. The generated code is production-ready with proper error handling, validation, and tests.

📚 Additional Resources

Common Commands

Quick Reference 
# Watch mode - regenerate on spec changes
kiro watch

# Validate specifications
kiro spec validate

# List all specifications
kiro spec list

# Generate with specific model
kiro generate --model claude-3-opus

# Dry run to preview changes
kiro generate --dry-run

# Rollback to previous generation
kiro rollback

🔧 Troubleshooting

Common Issues

⚠️
Installation fails: Ensure you have proper permissions. On macOS/Linux, you might need sudo for system-wide installation.
⚠️
Generation errors: Run kiro spec validate to check for specification syntax errors.
⚠️
API keys: Some models require API keys. Set them with kiro config set api_key YOUR_KEY

For more help, run kiro doctor or visit our troubleshooting guide.
